Open, self-scoring thermospheric drag service

ThermoSwarm Observatory BACKTEST

About 1,100 tracked objects act as sensors of upper-atmosphere density. Every day the observatory measures how wrong the NRLMSIS 2.1 model is at each altitude, forecasts drag 72 hours ahead with calibrated uncertainty, shows how that uncertainty changes collision risk, and scores every forecast — its own and any submitted model — once the truth is known. Forecasts are committed to a hash-chained public registry before they can be checked.

Backtest: the system replayed day by day over the ThermoSwarm 2025–26 record using only information available at each date. These are not pre-registered live forecasts; the live registry starts on the first automated run.

Sentinel: the whole catalogue, every day

Every tracked object is screened against every other for the next 72 hours. Each close approach gets a collision probability from a measured error model of public element sets plus today's storm-drag interval, the smallest avoidance burn that makes it safe, and the catalogue is searched for unannounced manoeuvres, break-ups, re-entries and drag-signature changes. How we know it works

  • Element-set error model: calibrated on 426,455 pairs of element sets from 1,281 objects (2025-10-01 to 2026-10-11); on objects held out of the fit, the 90% along-track bounds contained 80–94% of the real errors. Storms roughly double the along-track error of public element sets.
  • Storm-aware manoeuvre detection: on a year of element sets of non-manoeuvring objects, false alarms during storms fell from 5.62 to 2.12 per 1,000 checks against a detector without the swarm index (quiet: 1.2 vs 1.27); injected 0.2-km boosts were found 67% vs 49% of the time.
  • Re-entry windows: 157 predictions for 24 objects with known decay dates; median error 0.5 days at 7 days out; the 90% windows contained 90% of re-entries on held-out objects (small sample).
  • Screening completeness: checked against a brute-force search (every pair, 1-s steps, same refinement): no high-speed approach was missed. Burn displacements match a numerical orbit integration with Earth's oblateness to within 0.3% over five orbits.

Collision-risk impact

Each conjunction's collision probability (Pc) is recomputed with the drag uncertainty in today's bulletin added to the along-track position. Two different things can happen:

  • Riskier: somewhere inside the drag interval the Pc reaches a higher risk category than screened, so the screen understated the risk.
  • Diluted: the extra uncertainty spreads the Pc so thin that it drops a category. This does not mean the encounter is safer; it means the orbit is not known well enough for a low Pc to be reassuring.

Verify it yourself

Every day's forecasts are in registry/forecasts/; each line of registry/chain.jsonl holds the file's SHA-256 and a hash chained to the previous day. Run python -m observatory.pipeline --verify to recompute the chain. Submit your own model's forecasts as a JSON file in submissions/<team>/YYYY-MM-DD.json before the day's run (see SUBMITTING.md); they are scored with the same rules. Machine-readable feed: feed/backtest.json.
